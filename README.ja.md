# RelayAudit

### AI 中継サービス料金検証ツール

**再現可能な固定リクエスト、公開価格、実際の請求記録を使い、AI 中継サービスの課金額を検証します。**

内部ルーティングを推測せず、このテストで観測された Token 使用量と課金額が一致するかだけを確認します。

## 現在の対象範囲

現在のバージョンは Token 使用量と価格のみを検証し、速度は測定しません。

中継サービスの速度は、テスト地域とネットワーク経路、ノード負荷と同時実行数、ルーティング方針、上流サービスの状態、DNS と TLS の接続確立、テスト時間帯など、多くの要因に影響されます。1 つの地域または 1 回のリクエストの遅延だけでは、プラットフォーム全体のサービス品質を表せません。

将来のバージョンでは、速度テストを独立した評価軸として追加する予定です。複数地域、複数時間帯、複数ラウンドでサンプリングし、最初の Token までの時間、レスポンス完了時間、リクエスト成功率、変動幅を料金検証の結論とは分けて表示します。

## 概要

RelayAudit は、1 つまたは 2 つの OpenAI 互換エンドポイントへ再現可能な固定リクエスト群を送信し、返された `usage` を読み取ります。公開されているモデル価格から基準料金を計算し、ユーザーが入力したプラットフォームの実際の課金額と比較します。

プロジェクト全体がオープンソースです。誰でもテストコーパス、リクエストパラメータ、usage の正規化、料金計算式、レポート生成処理を確認し、自分の環境で実験を再現できます。これにより、結果の恣意的な選択や特定プラットフォームへの偏りを抑えます。

## 主な機能

- デフォルトでは 1 つのプラットフォームを検証し、必要に応じて意味的に同一のリクエストを 2 つのプラットフォームへ送信できます。
- 単一ターンの安定性、複数ターンのコンテキスト、キャッシュ再利用の 3 つをテストします。
- 現在のテスト項目、ラウンド、プラットフォーム、全体の進捗をリアルタイムで表示します。
- デフォルトでは組み込みの固定コーパスを使用し、詳細オプションから独自コーパスを有効化できます。
- 公開価格リポジトリから 5.6 モデルの価格を同期し、SHA-256 で価格ファイルを検証します。
- OpenAI 形式と Anthropic 形式で一般的な `usage` フィールドを正規化します。
- プラットフォームの課金額、基準となる予想課金額、相対誤差、実測倍率を計算します。
- 機密情報を除いた JSON エビデンス、HTML レポート、テキスト要約を出力します。
- API Key は現在のテストにだけ使用し、保存せず、レポートにも含めません。

## 実行方法を選ぶ

ホスト版とセルフホスト版は、まったく同じテストコーパス、価格同期、usage 正規化、料金計算式を使用します。

| 方法 | 適した用途 | API Key の経路 | エントリ |
| --- | --- | --- | --- |
| **Vercel ホスト版** | インストールせずすぐに使用 | ブラウザ → RelayAudit Vercel Function → 検証対象の中継サービス | [オンラインでテスト](https://relay-billing-verifier.vercel.app) |
| **セルフホスト版** | 独立検証、プライベートエンドポイント、厳格な認証情報管理 | ブラウザ → 自分の RelayAudit サービス → 検証対象の中継サービス | [公開ソースコードを見る](https://github.com/joey2001q-create/RelayAudit-AI-Billing-Verifier) |

> [!NOTE]
> ホスト版がアクセスできるのは、公開 HTTPS 中継エンドポイントだけです。localhost、プライベートネットワーク、HTTP エンドポイントをテストする場合はセルフホスト版を使用してください。

Node.js 20 以降が必要です。リポジトリをクローンし、ローカルで実行するか、自分の Vercel アカウントへデプロイします。

```bash

cd RelayAudit-AI-Billing-Verifier
npm ci

# 方法 1：ローカルで実行
npm start

# 方法 2：自分の Vercel アカウントへデプロイ
npx vercel
```

ローカル起動後、<http://127.0.0.1:4312> を開きます。次のボタンから、リポジトリの複製とデプロイを一度に実行することもできます。

## 使用手順

どちらのバージョンでも手順は同じです。

1. cURL、JSON、または 3 行形式の設定を貼り付けます。Base URL、API Key、モデルエイリアスを手動で入力することもできます。
2. `gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna` のいずれかを選択します。
3. 標準検証またはプロフェッショナル検証を実行し、各リクエストの進捗を確認します。
4. プラットフォームの請求明細から、このテストに対応する高精度な課金額を取得します。倍率のデフォルト値は `1` です。別の倍率を使用するプラットフォームの場合だけ変更します。
5. 結論を確認し、必要に応じてエビデンスを出力します。

5.6 モデルを選択すると、動的価格カタログからモデル名と価格が自動入力されます。独自モデルでは、詳細オプションからモデル名と 100 万 Token あたりの価格を入力します。README には重複する固定価格表を置かず、動的データソースとのずれを防いでいます。

価格は [`Wei-Shaw/model-price-repo`](https://github.com/Wei-Shaw/model-price-repo) から取得します。実行中のサービスは価格 JSON と対応する SHA-256 をダウンロードし、検証に成功した場合だけページを更新します。ネットワークが利用できない場合や検証に失敗した場合は、リポジトリに含まれる最新の有効なスナップショットを使用します。レポートには、リモート価格、組み込みスナップショット、ユーザー入力価格のどれを使用したかと、価格ファイルのハッシュが記録されます。

メンテナーは `npm run pricing:sync` を実行して組み込みスナップショットを更新できます。リポジトリの定期ワークフローも毎日更新を確認します。

詳細オプションで独自コーパスを有効にすると、入力した本文を固定入力として使用し、「`BILLING_TEST_OK` だけを返す」という短い出力制約も自動的に追加します。最大出力 Token のデフォルト値は `16` です。これは上限であり、出力 Token 数が正確にその値になることを保証するものではありません。ランダム生成、要約、書き換えを要求すると不要な出力 Token の変動が生じるため、検証用コーパスでは避けてください。

倍率はリクエスト完了後の第 3 ステップで入力し、デフォルト値は `1` です。倍率は料金検証にだけ使用され、中継サービスへ送信するリクエストには影響しません。プラットフォームに別の倍率がある場合は、`0.8` や `1.2` のように入力できます。

## 検証方法

```text
基準料金 = 通常入力料金 + キャッシュ読み取り料金 + キャッシュ作成料金 + 出力料金
倍率適用後の予想課金額 = 基準料金 × 公称倍率
実測倍率 = プラットフォームの課金額 ÷ 基準料金
相対誤差 = (プラットフォームの課金額 - 予想課金額) ÷ 予想課金額
```

デフォルトでは、相対誤差が `2%` 以下の場合に「公称倍率と一致」と表示します。これはツール独自の判定ルールであり、業界標準ではありません。小数点以下の切り捨て、四捨五入、課金反映の遅延によって小さな差が生じる場合があります。

## リクエストの一貫性

- すべてのテストで、固定コーパス、ラウンド識別子、メッセージ構造、生成パラメータを使用します。
- 2 プラットフォームテストでは、認証情報とプラットフォーム側のモデルエイリアスだけを変更し、意味的リクエストの SHA-256 を記録します。
- 複数ターンテストでは、固定した assistant メッセージで履歴を拡張し、ランダムなモデル応答を次のターンへ渡しません。
- キャッシュ再利用テストでは、まったく同じリクエスト内容を繰り返し送信します。
- `/v1/chat/completions` と `stream: false` を使用し、失敗したリクエストは自動再試行しません。
- モデルの応答内容は異なる場合があります。料金は各プラットフォームが実際に返した `usage` から個別に計算します。

「キャッシュ読み取り比率」は、総入力 Token に占めるキャッシュ読み取り Token の割合です。プラットフォーム内部の実際のキャッシュヒット率とは異なります。上流サービスがキャッシュ内訳を返さない場合、RelayAudit は `0%` とせず「未報告」と表示します。

## エビデンスの範囲

RelayAudit で確認できること：

- このテストで送信した再現可能な意味的リクエスト。
- プラットフォームが返した Token 使用量。
- ユーザーが入力した公開価格と倍率に対して、請求額が一致しているか。

RelayAudit で確認できないこと：

- 中継サービスが、表示している上流モデルを実際に呼び出したか。
- 中継サービスが上流へ支払う内部コスト。
- 公開されていないルーティング、キャッシュ、料金実装の詳細。
- 今回のテスト範囲外における長期的な課金動作。

したがって、レポートの結論は今回のテストで観測できた課金データだけを対象とします。

## セキュリティ

- Vercel ホスト版では、API Key はブラウザから Vercel Function へ一時的に送信され、Function がユーザー指定の中継サービスへリクエストします。プロジェクトは Key を永続化または意図的に記録せず、レスポンスやレポートにも含めません。
- セルフホスト版はデフォルトで `127.0.0.1` をリッスンします。API Key が通過するのは、ユーザー自身のブラウザ、ローカルの RelayAudit サービス、検証対象の中継サービスだけです。
- ホスト版は公開 HTTPS アドレスだけを許可し、localhost、プライベート、リンクローカル、予約済みアドレスを拒否します。ローカル版では、ユーザーのネットワーク環境に応じて HTTP やプライベートエンドポイントをテストできます。
- API Key を信頼できない宛先へ送らないよう、Base URL が検証対象プラットフォームのものであることを確認してください。
- 実際の Key を含むターミナル出力、スクリーンショット、設定ファイルをリポジトリへコミットしないでください。
- `.vercel` ディレクトリ、Vercel のログイン情報、実際の Key をリポジトリへコミットしないでください。
- レポートを出力する前に、プラットフォーム名、エンドポイント、業務情報を公開して問題ないか確認してください。
- 独自コーパスの本文はレスポンスや出力レポートに含まれません。レポートに記録されるのは、入力元、行数、文字数、SHA-256 だけです。

脆弱性報告の詳しい方法は [SECURITY.md](SECURITY.md) を参照してください。
